# Yandex Feed Editor

Веб-редактор XML-фида врачей для каталога Яндекса. Приложение позволяет загрузить существующий XML-фид, отредактировать его структуру через удобный интерфейс, проверить данные на типовые ошибки и скачать готовый XML.

Проект работает полностью в браузере: импорт и экспорт выполняются на стороне клиента, отдельный backend или база данных не используются.

## Возможности

- импорт XML-фида с диска;
- разбор секций `<shop>`, `<doctors>`, `<clinics>`, `<services>` и `<offers>`;
- редактирование данных площадки;
- создание, редактирование, дублирование и удаление врачей, клиник, услуг и предложений;
- автоматическая генерация ID для новых записей;
- выбор врача, клиники и услуги из существующих записей при создании предложения;
- справочник специальностей, используемый для подсказок при заполнении предложения;
- редактирование образования, опыта работы, сертификатов и отзывов врача;
- настройка цены, скидок и параметров записи для предложения;
- автоматическая генерация XML из текущего состояния редактора;
- просмотр сформированного XML непосредственно в интерфейсе;
- копирование XML в буфер обмена;
- скачивание готового XML-файла;
- очистка текущего фида;
- встроенная валидация данных с разделением ошибок и предупреждений;
- переход из списка ошибок непосредственно к проблемной записи;
- обнаружение неизвестных XML-тегов при импорте.

## Установка

Клонируйте репозиторий и установите зависимости:

```bash
git clone <repository-url>
cd yandex-feed-editor
npm install
```

После установки запустите приложение в режиме разработки:

```bash
npm run dev
```

Vite выведет локальный адрес приложения в терминале. По умолчанию это адрес вида `http://localhost:5173`.

## Production-сборка

Собрать production-версию:

```bash
npm run build
```

Результат сборки будет находиться в директории `dist/`.

Для локальной проверки production-сборки:

```bash
npm run preview
```

## Проверка кода

Для запуска Oxlint:

```bash
npm run lint
```

## Работа с приложением

### 1. Загрузка существующего фида

В интерфейсе выберите импорт XML и укажите файл с фидом.

Редактор разбирает XML и переносит данные в отдельные сущности:

- площадка;
- врачи;
- клиники;
- услуги;
- предложения.

Если в известных структурах обнаружены незнакомые XML-теги, приложение сохраняет список таких тегов и показывает предупреждение после импорта. Незнакомые элементы не переносятся в редактируемую модель и не генерируются обратно при экспорте.

### 2. Редактирование сущностей

Для каждой сущности доступны операции:

- добавить;
- изменить;
- продублировать;
- удалить;
- найти по поиску.

ID записей должны быть уникальными внутри соответствующего раздела. При создании новой записи приложение предлагает следующий свободный ID на основе существующих идентификаторов.

### 3. Создание предложения

`offer` связывает между собой:

- врача;
- клинику;
- услугу;
- специальность.

Дополнительно можно указать URL записи, цену, скидки и параметры доступности услуги: ОМС, онлайн-расписание, запись через сайт-поставщик, приём детей и взрослых, вызов на дом, телемедицину и признак базовой услуги.

### 4. Проверка фида

Раздел валидации автоматически пересчитывается при изменении данных.

Проверяются, в частности:

- версия фида;
- дата обновления;
- обязательные поля площадки;
- длина названия площадки;
- наличие и уникальность ID врачей, клиник, услуг и предложений;
- обязательные поля врачей и клиник;
- существование связанных врача, клиники и услуги в предложении;
- наличие специальности;
- соответствие специальности встроенному справочнику;
- корректность скидок относительно базовой цены;
- наличие валюты при заполненной цене;
- наличие `internal_id` у врача, клиники и услуги при включённом онлайн-расписании;
- наличие хотя бы одной базовой услуги у каждого врача.

Ошибки блокирующего характера и предупреждения отображаются отдельно. Из списка проблем можно перейти непосредственно к соответствующей записи.

### 5. Экспорт

XML строится автоматически из текущего состояния приложения. Его можно:

- просмотреть в редакторе;
- скопировать в буфер обмена;
- скачать как `.xml`.

Пустые необязательные значения не записываются в XML. Для повторяемых блоков врача (`education`, `job`, `certificate`, `review`) пустые записи также не экспортируются.

Блок `<price>` генерируется только при наличии базовой цены. Это предотвращает создание частично заполненного блока цены.

## Структура данных

Основная модель приложения состоит из пяти частей.

### `shop`

Общие данные фида:

- `version`;
- `date`;
- `name`;
- `company`;
- `url`;
- `picture`;
- `email`.

### `doctors`

Данные врачей, включая:

- идентификаторы и ФИО;
- описание и URL;
- стаж и дату начала карьеры;
- образование;
- опыт работы;
- сертификаты;
- степень, звание и категорию;
- количество отзывов;
- отзывы пациентов.

### `clinics`

Данные клиник:

- название;
- город и адрес;
- телефон и email;
- URL и изображение;
- внутренний ID;
- ID организации в Яндексе.

### `services`

Данные медицинских услуг:

- ID;
- название;
- код Минздрава (`gov_id`);
- описание;
- внутренний ID.

### `offers`

Связи между врачами, клиниками и услугами. Включают:

- ID предложения;
- URL записи;
- параметры записи;
- цену и скидки;
- врача, клинику и услугу;
- специальность;
- дополнительные признаки приёма;
- признак базовой услуги.

## Архитектура

Приложение представляет собой одностраничный React-интерфейс без серверной части.

Основная логика сосредоточена в `src/App.jsx`:

- `parseFeedXML()` — импорт и разбор XML;
- `buildXML()` — сериализация внутренней модели обратно в XML;
- `validateFeed()` — проверка данных;
- `suggestNextId()` / `nextId()` — генерация ID;
- React state — хранение текущего фида и состояния интерфейса;
- компоненты форм — редактирование отдельных типов сущностей;
- `EntityTable` — отображение списков сущностей;
- `ValidationPanel` — отображение ошибок и предупреждений;
- `EditorDrawer` — форма редактирования записи.

`src/main.jsx` является точкой входа React-приложения.

`src/index.css` и `src/App.css` содержат стили интерфейса.

`public/` содержит статические ресурсы, используемые приложением.

## Конфигурация

Специальная конфигурация окружения не требуется. В проекте отсутствуют обращения к backend API и переменным окружения для работы редактора.

Конфигурация Vite находится в `vite.config.js` и подключает React-плагин.

## Важные особенности

### Работа только на клиенте

Файл XML читается через браузерный `FileReader`. После импорта данные хранятся в React state. Серверу они не отправляются.

### XML генерируется из состояния приложения

Редактор не изменяет исходный XML напрямую. При экспорте он заново формирует XML на основе структурированных данных `shop`, `doctors`, `clinics`, `services` и `offers`.

Поэтому элементы XML, которые приложение не поддерживает в своей модели, не сохраняются при повторном экспорте.

### Экранирование XML

Перед записью текстовых значений в XML выполняется экранирование специальных символов (`&`, `<`, `>`, кавычки и апострофы), чтобы пользовательские значения не ломали XML-разметку.

## Ограничения текущей версии

- Нет backend-сервера и постоянного хранилища данных.
- Данные текущего сеанса не сохраняются в `localStorage` или `sessionStorage`.
- Импорт поддерживает только XML-структуры, которые предусмотрены текущим парсером.
- Неподдерживаемые XML-теги фиксируются как предупреждения, но не сохраняются при экспорте.
- Валидация проверяет набор правил, реализованных в приложении, и не заменяет финальную проверку фида средствами самого Яндекса.

## Разработка

При изменении структуры XML рекомендуется синхронно обновлять три части приложения:

1. фабрику начальных данных соответствующей сущности;
2. `parseFeedXML()` для импорта;
3. `buildXML()` и `validateFeed()` для экспорта и проверки.

Для новых полей интерфейса также необходимо обновить соответствующую форму редактирования.
